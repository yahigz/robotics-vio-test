# Запуск DBA-Fusion в Colab (утренний чек-лист)

Локальная часть (OpenVINS, ORB-SLAM3 на garden/campus/park) уже посчитана: `results/summary/all.md`.
Осталась только ветка DBA-Fusion, ей нужен GPU, поэтому она идёт в Colab.

## Вариант A: я запускаю сам через colab-mcp
1. Перезапусти Claude Code в `~/mipt/robotics/vio-bench` (чтобы инструменты `colab-mcp` загрузились в сессию).
2. Открой https://colab.research.google.com, войди в аккаунт, Runtime → Change runtime type → **T4 GPU**.
3. Проверь Secrets (значок ключа слева), у всех включён «Notebook access»:
   `GITHUB_TOKEN`, `CLEARML_API_ACCESS_KEY`, `CLEARML_API_SECRET_KEY`, `CLEARML_API_HOST`, `CLEARML_WEB_HOST`, `CLEARML_FILES_HOST`.
4. Скажи мне «запускай DBA-Fusion». colab-mcp попросит подтвердить подключение во вкладке браузера.

## Вариант B: руками (если MCP не заведётся)
1. Шаги 2–3 выше.
2. File → Upload notebook → `methods/dbafusion/dbafusion_colab.ipynb`.
3. Runtime → **Run all**. На ячейке Drive согласись на монтирование (это только кеш сборок, несколько сотен МБ).
   Если места на Drive нет, поставь `USE_DRIVE_CACHE = False` в ячейке параметров.
4. Время: первая сессия ~1–1.5 ч на сборку (GTSAM 20–45 мин, CUDA-расширения 8–20 мин), потом каждая последовательность
   ~10–25 мин (скачивание + ректификация + прогон). Вкладку держи открытой (бесплатный Colab отключает при простое).
5. Когда закончится, на ноуте: `pixi run fetch-colab`. Он заберёт траектории из ClearML, пересчитает метрики
   и обновит `results/summary/all.md`.

## Если что-то упало
- Ячейка сборки GTSAM или расширений: пришли мне последние ~50 строк вывода, ноутбук печатает их сам.
- Быстрая проверка без полного прогона: `ROVER_MAX_SECONDS = 20` (или `MAX_FRAMES = 100`) в ячейке параметров.
  Результаты таких прогонов помечаются как smoke и в итоговую таблицу не попадают.
- Последовательности независимы: падение одной не останавливает остальные; уже готовые пропускаются при перезапуске.
